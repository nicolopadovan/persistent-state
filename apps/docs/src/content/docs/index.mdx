This page describes what persistent-state does, who it is for, how stable it is and where to go next.

:::caution[0.x releases may break]
persistent-state is in its 0.x series. Every 0.x minor release may contain breaking changes; patch releases never do.
Pin the minor version you depend on and read the [migration page](/help/migrating/) before you upgrade. Version 1.0.0
ships when the roadmap core is done.
:::

## What is persistent-state?

persistent-state is a small library that keeps a piece of React state in the browser's storage and restores it on the
next visit. You declare each key once with `persistentState()`, choosing where it lives: a cookie, `localStorage` or
`sessionStorage`. You then read and write it in components with `useStoredState()`.

Cookies are the one storage a server can read. With the Next.js entry point, a Server Component reads the cookie
values of the request, so the first render already matches what the visitor stored, without a flash of default state.

## Who is it for?

persistent-state is for React and Next.js applications that remember small preferences, such as a theme, a layout or a
dismissed notice, and want them to survive reloads, stay in sync across tabs and, for cookies, render correctly on the
server. It is not a global state manager and not a replacement for a database.
